## 分课核心知识点复盘

### 第 1 课：Agent 本质与手写 ReAct（正则解析版）

**核心目标**：搞懂 Agent ≠ 大模型，理解最底层的运行逻辑

1. **核心范式：ReAct 循环**
Agent = 大模型 + 工具 + 循环，无限执行三步：
   - Thought（思考）→ Action（行动 / 调用工具）→ Observation（观察结果）
   直到得出最终答案。
2. **核心组件**
   - 工具（Tools）：Agent 的 “手脚”，是可执行的函数
   - 短期记忆：`messages` 对话列表，每轮思考和结果都存入
   - 系统提示词：定义 Agent 的行为规则和输出格式
3. **实现方式**：用正则表达式解析大模型的文本输出，提取 Action 和 Action Input
4. **经典坑点**：大模型输出格式不稳定（多引号、多空格），必须做参数清洗
5. **工程意义**：所有 Agent 的底层原型，面试 “手写过 Agent 吗” 的核心考点

---

### 第 2 课：搜索工具 + 记忆系统管理

**核心目标**：让 Agent 能获取实时信息，解决上下文溢出问题

1. **Agent 三级记忆体系**

表格

| 记忆类型 | 存储方式 | 作用 |
| --- | --- | --- |
| 短期记忆 | 内存 messages 列表 | 当前任务上下文，速度快、容量有限 |
| 长期记忆 | 向量数据库（RAG） | 跨会话持久化知识 |
| 摘要记忆 | 文本压缩总结 | 平衡容量与信息完整性 |
2. **滑动窗口记忆**：`trim_messages` 函数，永远保留 system 规则，只丢弃早期对话，是性价比最高的上下文优化方案
3. **搜索工具选型**
   - 学习 / 玩具：自研网页爬虫
   - 生产环境：**Tavily 等专业 Agent 搜索 API**（稳定、合规、结果结构化、无反爬风险）
4. **工程意义**：Agent 具备了真实世界信息获取能力，具备实用价值

---

### 第 3 课：原生 Function Calling（工业级标准）

**核心目标**：抛弃正则解析，用大模型官方标准做工具调用

1. **为什么抛弃正则**
   - 格式不稳定、复杂参数无法解析、浪费 token 在格式约束上
2. **Function Calling 工作流**
   1. 传入工具定义（JSON Schema 格式）
   2. 大模型决策是否调用工具、调用哪个、传什么参数
   3. 返回结构化 `tool_calls` 对象（包含工具 ID、名称、参数）
   4. 执行工具，把结果以 `role: "tool"` 的消息回传
   5. 循环直到结束
3. **核心优势**
   - 参数是标准 JSON，稳定可靠
   - 支持**并行调用**多个工具，效率更高
   - 所有大模型和框架的通用标准
4. **工程意义**：这是工业界 100% 在用的工具调用方式，是所有 Agent 框架的底层基础

---

### 第 4 课：Plan-and-Execute 规划型 Agent

**核心目标**：从 “走一步想一步” 到 “先规划后执行”，处理复杂任务

1. **三层架构思想**
   - **规划层（Planner）**：拆解大任务为有序子任务
   - **执行层（Executor）**：逐个完成子任务，调用工具
   - **汇总层（Summarizer）**：整合所有结果，输出最终报告
2. **ReAct vs Plan-and-Execute**
   - ReAct：灵活、实时调整，适合简单问答
   - Plan-and-Execute：有条理、不遗漏、质量高，适合调研、写作等复杂流程任务
3. **工程思想**：职责分离，分层设计，每层只做一件事，可独立优化替换
4. **工程意义**：复杂业务 Agent 的标准架构思路，体现工程化思维

---

### 第 5 课：LangGraph 入门 —— 图状态机

**核心目标**：用工业级标准框架重构 Agent，理解图架构的价值

1. **LangGraph 三大核心概念**
   - **State（状态）**：所有节点共享的数据对象，不止是消息，还包含业务数据
   - **Node（节点）**：执行具体逻辑的单元（调用模型、执行工具等）
   - **Edge（边）**：定义执行顺序，分普通边和条件边
2. **为什么用 Graph 不用 Chain**
   - 天然支持循环（Agent 的思考 - 行动循环）
   - 全局状态共享，数据流转清晰
   - 灵活的条件分支，支持复杂决策
   - 可观测性强，便于调试、回溯、持久化
3. **对应关系**：手写版 vs LangGraph 版

表格

| 手写版 | LangGraph 版 |
| --- | --- |
| while 循环 | 图的循环边 |
| messages 列表 | State.messages |
| 调用大模型决策 | agent 节点 |
| 执行工具函数 | tools 节点 |
| if 判断结束 | 条件边路由函数 |
4. **工程意义**：正式进入生产级技术栈，校招 / 社招 Agent 岗位最高频考点

---

### 第 6 课：多 Agent 协作（Multi-Agent）

**核心目标**：通过角色分工，提升复杂任务的输出质量

1. **核心思想：专业化分工**
单 Agent 是 “全能选手”，什么都干但不精；多 Agent 每个角色只专注一个领域，用更精准的提示词输出更高质量结果。
2. **经典实现：三角色写作团队**
   - 研究员 Agent：搜索资料，整理事实
   - 撰稿人 Agent：基于素材撰写内容
   - 审稿人 Agent：质量检查，通过 / 打回重写
3. **关键设计：反馈闭环**
审稿人打回 → 撰稿人重写 → 再审，形成质量控制闭环，比一次输出质量高得多
4. **状态扩展**
从纯消息列表扩展到业务状态：`topic`、`draft`、`review_passed`、`rewrite_count`
5. **单 Agent vs 多 Agent**

表格

| 维度 | 单 Agent | 多 Agent |
| --- | --- | --- |
| 角色 | 全能型 | 专业化分工 |
| 输出质量 | 中等 | 更高，各环节专业 |
| 可维护性 | 差 | 好，角色独立可替换 |
| 适用场景 | 简单问答、工具调用 | 复杂流程、内容生产、团队协作 |
6. **工程意义**：企业级复杂 Agent 系统的标准架构模式
