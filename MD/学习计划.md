# Agent 开发学习计划（从 0 到企业可用）

> 依据《Agent 开发入门学习路线（求职导向）· 2026 版》制定
> 周期：16 周，每天有效投入 3-4 小时
> 参考起止：2026-09-07 至 2026-12-27（日期可整体平移，周次不变）
> 使用方法：完成一项勾一项；每周日复盘一次；**阶段过关标准不达标，不进入下一阶段**

---

## 使用本计划的三个原则

1. **产出物优先**：每阶段有硬性产出。没有产出 = 没有学会。
2. **过关才走**：赶进度是这条路线上最常见的失败方式。
3. **边做边写**：踩坑随手记进笔记，第 13 周起整理成博客。

**前提说明**：本计划假设你已有基础编程能力（至少一门语言 + 基本数据结构）。如果连 Python 基础语法都不熟，在第 1 周前额外预留 2 周补 Python 基础（函数、类、异常、包管理）。

## P1 · 工程底座 + 成为重度用户（第 1-3 周）

**目标**：从"会写代码"升级为"能写 AI 后端服务"，并建立对 Agent 的体感。

### 第 1 周（9/07 - 9/13）：Python 异步 + 类型化

- [x] 学 `async/await`：事件循环、协程、`asyncio.gather`、超时与取消
- [x] 学类型注解 + Pydantic：模型定义、校验、嵌套、序列化
- [x] 练习：写一个并发抓取 10 个 URL 的异步脚本（带超时和重试）
- [x] 跑通模型 API 三种调用：普通、流式返回、JSON Mode 结构化输出
- [x] 日常开始用 Cursor / Claude Code 写代码，记录它哪里好用、哪里犯蠢

### 第 2 周（9/14 - 9/20）：FastAPI + SSE 流式输出

- [ ] FastAPI 基础：路由、Pydantic 请求/响应模型、异常处理
- [ ] 实现 `POST /chat`：接收消息，返回模型回复
- [ ] 实现 SSE 流式接口：打字机效果（**本阶段核心练习**）
- [ ] 加鉴权（API Key Header）和简单限流
- [ ] 能讲清：SSE / 普通 HTTP / WebSocket 三者的区别与取舍
- [ ] 反复练：30 分钟内从零搭出带流式输出的对话接口

### 第 3 周（9/21 - 9/27）：存储 + 工具链 + 重度用户

- [ ] MySQL 存对话历史（用 SQLAlchemy 或 SQLModel）
- [ ] Redis 存会话临时状态
- [ ] Docker：给对话服务写 Dockerfile，容器化跑通
- [ ] Linux 常用命令 + Git 规范提交（从本周起保持每日 commit）
- [ ] 用 Coze 或 Dify 搭一个带插件的 Bot 玩透，写 300 字体验记录
- [ ] 给项目写 README：架构说明 + 本地运行步骤

**P1 产出物**：GitHub 稳定 commit 记录 + 一个支持 SSE 流式输出的大模型对话接口（含 README）

**P1 过关标准**
- [ ] 30 分钟内从零搭出带流式输出的对话接口
- [ ] 能解释 SSE 与普通 HTTP 响应的区别
- [ ] 能说清 Agent 场景为什么必须用异步

## P2 · 手写 Agent + RAG 全链路（第 4-8 周）

**目标**：不依赖任何框架，从零实现 Agent 核心循环。这是与"只会调框架"的人拉开差距的阶段。

### 第 4 周（9/28 - 10/04）：手写 ReAct 循环（禁用一切框架）

- [ ] 理解 ReAct：Thought → Action → Observation → 终止
- [ ] 纯 `while` 循环 + 字符串解析实现
- [ ] 终止条件：最大步数 / 模型给出最终答案
- [ ] 防死循环：步数上限、重复动作检测
- [ ] 实现前 2 个工具（如：计算器、获取当前时间）
- [ ] 记录踩坑：模型不按格式输出时怎么办

### 第 5 周（10/05 - 10/11）：Function Calling 与工具设计

- [ ] 用原生 Function Calling 重构第 4 周的手工解析
- [ ] 工具 Schema 设计：命名清晰、描述排除错误解读、参数收窄
- [ ] 参数校验（Pydantic）+ 失败错误回传（错误信息写给模型看、可恢复）
- [ ] 再加 2-3 个工具（如：读文件、网络搜索、执行代码）
- [ ] 自测面试题："Schema 怎么设计模型才能用对？"

### 第 6 周（10/12 - 10/18）：Context Engineering + 项目①收尾

- [x] 多轮对话历史管理：裁剪策略、超长对话摘要压缩
- [x] 上下文溢出处理：token 计数、丢弃策略
- [x] 思考并记录：什么信息、什么时机进入上下文
- [ ] 项目①收尾：README + 架构图 + 工具错误回传设计说明
- [ ] 对照路线 STEP 6 项目①要求逐条自查

### 第 7 周（10/19 - 10/25）：RAG 上半场（解析 → 检索）

- [ ] 文档解析：PDF / Markdown / 网页 → 纯文本
- [ ] 分块：先固定长度，再改语义分块，两种都保留可切换
- [ ] Embedding 选型，向量化入库（先用 Chroma）
- [ ] 检索：向量检索 → 混合检索（向量 + 关键词 BM25）
- [ ] 接入 Rerank 重排模型

### 第 8 周（10/26 - 11/01）：RAG 下半场（溯源 → 评估）+ 项目②收尾

- [ ] 引用溯源：回答标注来源段落与编号
- [ ] 自建 20-30 条评测问答对，人工统计准确率
- [ ] 对比实验：固定长度 vs 语义分块，记录具体数字（X% → Y%）
- [ ] 项目②收尾：README + 引用效果截图 + 对比实验数据
- [ ] 记录一次 RAG 答错 case：定位是检索问题还是生成问题

**P2 产出物**：项目① 不依赖框架的手写 ReAct Agent（3-5 个工具、错误处理、防死循环、架构图）；项目② 带引用溯源的知识库问答 Agent（含对比实验）

**P2 过关标准**
- [ ] 能手写 200 行以内的 ReAct 循环
- [ ] 能说清分块策略、混合检索、Rerank 各解决什么问题
- [ ] 能解释 RAG 为什么答错，以及怎么定位（检索 or 生成）

## P3 · 框架 + MCP + 多 Agent（第 9-12 周）

**目标**：用工业级框架重构 P2 手写代码，掌握 MCP，搭出多 Agent 系统，并开始投递。

### 第 9 周（11/02 - 11/08）：LangGraph 入门

- [ ] 核心概念：State / Node / Edge / 条件分支
- [ ] 用 LangGraph 重写项目①的 ReAct（对照手写版，理解框架替你解决了什么）
- [ ] 并行节点 + 状态合并
- [ ] Checkpoint 持久化：断点续跑
- [ ] Time-travel 调试用一次

### 第 10 周（11/09 - 11/15）：MCP 协议 + 自建 Server

- [ ] 搞懂架构：Host / Client / Server 三者关系
- [ ] 三大原语：Tools / Resources / Prompts
- [ ] 两种传输：stdio 与 HTTP+SSE，各自适用场景
- [ ] 动手：写一个自己的 MCP Server（如：读本地文档库 / 查数据库）
- [ ] 发布到 npm 或 PyPI，验证能在 Claude Code / Cursor 里跑通
- [ ] 安全练习：只读凭证、最小权限、写操作加审批边界

### 第 11 周（11/16 - 11/22）：多 Agent 系统（项目③主体）

- [ ] Supervisor 模式：规划 → 执行 → 整理 → 审核
- [ ] Human-in-the-loop：人工审核节点（interrupt 机制）
- [ ] Agent 间通信与共享状态
- [ ] CrewAI 快速过一遍（了解定位即可，限时 2 小时）

### 第 12 周（11/23 - 11/29）：项目③收尾 + 开始投递

- [ ] 项目③组装：LangGraph 多 Agent + 自建 MCP Server + Docker 部署
- [ ] README：状态图 + 架构说明 + 关键决策记录（为什么这么做）
- [ ] **开始投 10 家练手公司**（AI 创业公司、传统企业 AI 部门优先）
- [ ] 每场面试后记录被问倒的问题，列入下周补强清单

**P3 产出物**：项目③ 多 Agent 系统（checkpoint 断点续跑 + 人工审核节点 + MCP 外接）；项目④ 已发布可用的 MCP Server

**P3 过关标准**
- [ ] 能画出 LangGraph 状态图并解释每个节点职责
- [ ] 能手写一个可用的 MCP Server 并说清三大原语
- [ ] 能说清什么场景不该用框架（单 Agent + 2-3 工具的线性流程手写更好）

## P4 · 生产化 + 求职冲刺（第 13-16 周）

**目标**：把项目从"能跑"改造成"敢上线"。这是 Demo 和 Offer 之间真正的分水岭。

### 第 13 周（11/30 - 12/06）：可观测性 Tracing

- [ ] Docker 自托管部署 Langfuse
- [ ] 接入主项目：每次 LLM 调用、工具调用、状态转移都记成 Span
- [ ] 拿到 Tracing 面板截图（三件套之一）
- [ ] 从 Trace 里找一个失败 case，写根因分析（工具描述歧义 or 模型推理问题）

### 第 14 周（12/07 - 12/13）：Eval 评估体系

- [ ] 评测集扩到 50 条（优先从真实 Trace 里筛）
- [ ] LLM-as-Judge + 代码断言（工具调没调对、顺序对不对、格式合规吗）
- [ ] 跑一次回归：改 Prompt 前后对比分数
- [ ] 出 Eval 报告（三件套之二）：准确率 / 召回率 / 幻觉率量化数字
- [ ] 把 eval 挂进 CI，当发布门禁

### 第 15 周（12/14 - 12/20）：成本 + 安全 + 上线

- [ ] Token 监控，整理成本账单（三件套之三）
- [ ] 优化：Prompt Caching、模型分级路由（简单任务给小模型）
- [ ] 安全自查：工具权限最小化、危险操作审批门、工具返回值按不可信输入处理
- [ ] 云服务器上线：Docker + CI/CD，全链路亲手走一遍

### 第 16 周（12/21 - 12/27）：求职冲刺

- [ ] 简历改造：全部量化（例："混合检索 + Rerank，自建 50 条评测集验证，准确率 62% → 89%"）
- [ ] 技术博客整理发布：至少 5 篇，覆盖 RAG / LangGraph / MCP / Eval 四个主题
- [ ] 每个项目准备"决策 → 坑 → 结果"面试叙事
- [ ] 继续投递 + 复盘，简历迭代到第 2 版以上
- [ ] 对照路线 STEP 8 考点清单逐条自测，答不上的立即补

**P4 产出物**：主项目三件套（Tracing 截图 + Eval 报告 + 成本账单）+ 5 篇博客 + 量化简历

**P4 过关标准**
- [ ] 能完整讲一次线上故障排查：Trace 定位节点 → 根因判断 → 改了什么 → 如何加进 eval 防回归
- [ ] 能答出："Agent 上线后，怎么知道它还在正常工作？"（Trace 埋点 → 在线评估 → 告警 → 人工标注 → 回归数据集 → CI 门禁闭环）

## 每日节奏建议

| 时段 | 内容 | 时长 |
| --- | --- | --- |
| 学习 | 读文档 / 看教程，只学当天要用的 | 1 小时 |
| 动手 | 写代码、跑通、改坏再修好 | 2-3 小时 |
| 记录 | 踩坑笔记 + git commit | 15 分钟 |

周末节奏：一半时间推进项目产出物，一半时间复盘本周内容（能不看资料复述出来才算会）。

## 每周复盘模板（每周日，20 分钟）

1. 本周产出物是什么？（没有产出 = 白学）
2. 本周被卡住最久的问题是什么，怎么解决的？
3. 关掉资料，能复述本周学的核心概念吗？
4. 下周最重要的三件事是什么？

## 里程碑速查

- **第 3 周末**：SSE 对话接口跑通 → 具备"能写 AI 后端"的证明
- **第 6 周末**：手写 ReAct Agent 完成 → 具备"懂原理"的证明
- **第 8 周末**：RAG 项目带引用与对比数据 → 具备"懂业务链路"的证明
- **第 12 周末**：多 Agent + MCP Server + 开始投递 → 具备"可投递"状态
- **第 16 周末**：三件套 + 博客 + 量化简历 → 具备"可面试、可谈薪"状态

## 避坑速查（每周对照一次）

- 没有从零独立做过，只跟着教程敲 = 等于零。检验：能不能从空白文件复现
- 陷入 Transformer 论文 / 数学推导 = 立即停止，去写代码
- 把 Dify/Coze 当主业 = 立即停止，会用即可
- 学了框架就不手写原理 = 薪资差一档，P2 的手写不能跳
- 只做不写不表达 = 项目等于不存在，坚持记笔记
