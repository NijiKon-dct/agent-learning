# Agent 开发入门学习路线（求职导向）

> **◆ 2026 版 · 求职优先导向**

## 从应届生到能拿 Offer 的 Agent 开发工程师

这份路线的唯一目标是**让你在最短时间内具备可投递、可面试、可谈薪的能力**，不是让你系统学完 AI。所有内容按「招聘方是否真的会为此买单」排序，能砍的都砍了。

**核心判断**：这是 **2026 校招缺口最大、对本科生最友好的 AI 赛道**。它考的是后端工程 + LLM 特性理解，**不需要硕士、不需要发论文、不需要预训练模型**。软件工程背景是优势不是劣势。

**真正的门槛**：不是会不会写 Prompt，而是**能不能让 Agent 稳定运行**。行业数据：**88% 的生产级 Agent 部署都出过事故**。会搭 Demo 的人一抓一把，能把 Demo 做成服务的人很少。

**最快的路径**：**3 个可展示项目 + 1 个持续更新的技术博客**，胜过十张网课结课证书。当 HR 搜你名字能搜到内容时，学历的权重就会下降。

## STEP 0 · 先搞清楚你在竞争哪个岗位

"Agent 开发"在招聘市场上至少是三种完全不同的工作。选错了方向，学得再努力也进不去面试间。

| 岗位类型 | 实际工作内容 | 学历门槛 | 对你的建议 |
| --- | --- | --- | --- |
| **Agent 应用开发**<br>Application / AI Engineer | 基于现成商用或开源大模型，用 LangGraph 等框架搭建业务智能体：知识库问答、数据分析助手、智能客服、办公自动化。本质是 **后端工程 + LLM 集成**。 | 本科为主<br>✓ 大量校招岗 | 主攻方向 |
| **Agent 平台 / Infra**<br>Runtime / Platform | 做 Agent Runtime、沙箱执行环境、多 Agent 调度框架、记忆与上下文抽象层、可观测平台。偏分布式系统。 | 本科+，但偏好 2-3 年后端经验 | 工作的第 2-3 年再切 |
| **大模型算法**<br>LLM Research / SFT | 预训练、SFT、RLHF、模型压缩、推理优化。要读论文、跑实验。 | 硕士起步 | 别碰（性价比极低） |

> **✓ 为什么软件工程背景反而是加分项**
>
> 翻遍 2026 年的 Agent 岗位 JD，高频出现的是：**异步编程、接口设计、状态管理、缓存、队列、Docker、可观测性、成本控制**——这些全是传统后端技能。而行业里真正的共识是：生产级 Agent **"是一个最不可预测的组件是语言模型的分布式系统"**。招人的公司最缺的不是懂 Transformer 的人，是懂**局部失败、幂等性、爆炸半径**的人。这正是科班工程训练给的东西。

> **⚠ 一个必须提前接受的现实**
>
> 大部分 JD 写着"1-3 年经验"、"至少参与过一个完整 Agent 系统开发"。你没有工作经验，唯一的破解方式是**用项目证明你做过完整链路**——从任务定义 → 工具封装 → 编排 → 评估 → 部署上线，而不是只交一个 `main.py`。

## STEP 1 · 技能地图：六层金字塔

从下往上按优先级排列。**底下三层决定你能不能过简历关，上面三层决定你能不能过技术面。**

**六层技能金字塔（从上到下）**

- **L6 · 生产化与 AgentOps**：Eval 评估体系 · Tracing 可观测 · 成本控制 · 安全与权限 · 分水岭
- **L5 · 编排与多 Agent**：LangGraph 状态图 · 规划与执行 · 记忆机制 · HIL 人工介入
- **L4 · MCP 协议**：Tools / Resources / Prompts · 自建 MCP Server · 2026 新增
- **L3 · Agent 核心机制**：Function Calling · ReAct/Plan-Execute · Context Engineering
- **L2 · RAG 全链路**：解析 · 切分 · 向量化 · 混合检索 · 重排 · 引用溯源
- **L1 · 工程底座**：Python 异步 · FastAPI/SSE · MySQL/Redis/向量库 · Git/Docker/Linux

> **◆ 关于学习顺序的一个反直觉建议**
>
> 几乎所有教程都让你从 LangChain 开始。**不要。**先用原始 API 手写一遍 Agent 循环，踩一遍坑（工具调用失败怎么重试、上下文怎么不炸、循环怎么停下来），再去学框架。这样你在面试时能讲清楚"框架到底在替我解决什么问题"——这个问题**能直接区分出用过框架的人和懂 Agent 的人**。

## STEP 2 · 四阶段 16 周执行计划

按每天有效投入 3-4 小时估算。每个阶段都有**明确的产出物**和**过关标准**——没达标就不要往下走，赶进度是这条路线上最常见的失败方式。

### P1 · 工程底座 + 成为重度用户（第 1–3 周）

**目标：**把"会写代码的应届生"升级成"能写 AI 后端服务的应届生"，同时建立对 Agent 的体感——你没深度用过 Agent，就设计不出好用的 Agent。

**学什么**

- **Python 异步**：`async/await`、类型注解（主流框架重度依赖）、异常与重试、Pydantic 模型
- **FastAPI**：RESTful 接口、**SSE 流式输出**（打字机效果全靠它）、请求校验、限流、鉴权
- **大模型 API**：申请 Key，跑通首次调用、流式返回、结构化输出（JSON Mode）
- **工具链**：Git 规范提交、Linux 常用命令、Docker 基础
- **当重度用户**：日常用 Cursor / Claude Code 写代码；用 Coze 或 Dify 搭一个带插件的 Bot 玩透

**为什么这么安排**

- **异步是硬性要求**：Agent 场景天然是"一直在等模型回包"，JD 里 async 几乎必考
- **SSE 是显学**：面试高频问"怎么实现流式输出"，答不出 HTTP 分块传输基本凉一半
- **不做过度投入**：数据结构算法只需刷中等难度，HTTP / REST 规范要懂，不用啃完整个 CS 课程体系
- **用户视角很关键**：知道 Agent 在哪里卡顿、在哪里犯蠢，是后面做工具设计和上下文管理的前提

**◆ 产出物**：GitHub 上出现稳定 commit 记录；一个用 FastAPI 包装的**支持 SSE 流式输出的大模型对话接口**，能本地跑通并有 README。

**过关标准 →** 能在 30 分钟内从零搭出一个带流式输出的对话接口，并解释清楚 SSE 与普通 HTTP 响应的区别。

### P2 · 手写 Agent + RAG 全链路（第 4–8 周）

**目标：**不依赖任何框架，从零实现 Agent 的核心循环。这一步是你和"只会调 LangChain"的人拉开差距的地方，也是面试里最有话说的部分。

**学什么**

- **手写 ReAct 循环**：Thought → Action → Observation → 终止条件 → 防死循环。纯 `while` 循环 + 字符串解析，不用任何框架
- **Function Calling / Tool Use**：工具 Schema 设计、参数校验、调用失败的错误回传（**错误信息要写给模型看，让人能恢复**）
- **Context Engineering**：这已经取代了 Prompt Engineering 成为更高杠杆的技能——决定什么信息在什么时机进入上下文窗口
- **RAG 全链路**：文档解析 → 切分策略 → Embedding → 向量库（入门 Chroma，进阶 Qdrant/Milvus）→ 混合检索 → Rerank 重排 → **引用溯源**
- **失败模式**：识别幻觉、上下文溢出、工具误用、无限循环这 5 类 Agent 典型故障

**关键判断**

- **工具设计是 2026 年的核心新技能**：写一个 MCP 工具很容易，写一个模型在模糊场景下也能用对的工具很难。要像 API 设计师 + 老师一样思考：名字清晰、输入收窄、描述排除错误解读、错误信息可恢复
- **RAG 不是"塞文档进向量库"**：企业最在意的是**可追溯性和幻觉率**。你的项目必须做到回答带引用来源
- **别急着上复杂架构**：先把 happy path 跑通，再逐步加健壮性
- **存储层**：MySQL 存结构化（对话历史），Redis 存临时状态，向量库存长期记忆

**◆ 产出物**：**项目 ①**：不依赖框架的手写 ReAct Agent，带 3-5 个工具，有完整的错误处理与循环保护，README 里画清楚架构图。
**项目 ②**：带引用溯源的知识库问答 Agent（可传自己的文档，回答标注来源段落）。

**过关标准 →** 能手写一个 200 行以内的 ReAct 循环；能说清楚分块策略、混合检索、Rerank 各自解决什么问题；能解释为什么 RAG 会答错。

### P3 · 框架 + MCP + 多 Agent（第 9–12 周）

**目标：**用工业级框架把 P2 的手写代码重构成可维护系统，并掌握 MCP——这是 2026 年 JD 里出现频率增长最快的关键词。

**学什么**

- **LangGraph（主攻）**：State / Node / Edge / 条件分支 / 并行节点 / **Checkpoint 持久化** / Time-travel 调试 / **Human-in-the-loop**
- **MCP 协议**：Host / Client / Server 架构，三大原语 Tools / Resources / Prompts，stdio 与 HTTP+SSE 传输
- **动手写 MCP Server**：用 TypeScript 或 Python 写一个（比如"读公司内部文档"），**发布并能在 Claude Code / Cursor 里跑起来**
- **CrewAI（了解即可）**：角色化多 Agent，20 行出一个原型，适合快速验证想法
- **多 Agent 协作**：任务分解、Agent 间通信、Supervisor 模式、共享状态与冲突处理

**关键判断**

- **LangGraph 是求职首选**：生产成熟度最高、JD 命中率最高、LangSmith 生态最完整。虽然学习曲线最陡，但它值得
- **MCP 的战略价值**："一次写好工具，跨所有 MCP 兼容系统复用"，正在成为 Agent 连接外部世界的事实标准，就像 REST 之于 Web 服务
- **别把 Dify/Coze 当主业**：低代码是公司给非工程师用的，你靠它拿不到溢价，而且抽象层很快会变成天花板。**会用、能讲清楚利弊就够**
- **框架不是万能的**：单 Agent + 2-3 个工具的线性流程，手写往往优于上框架。面试时能讲出这个判断，是加分项

**◆ 产出物**：**项目 ③**：用 LangGraph 重构的**多 Agent 系统**（例如：研究助理 = 规划 → 搜索 → 整理 → 出报告），带 checkpoint 断点续跑和人工审核节点。
**项目 ④**：一个发布出去的 MCP Server（npm 或 PyPI），最好带 100+ star 的野心。

**过关标准 →** 能画出 LangGraph 的状态图并解释每个节点的职责；能手写一个可用的 MCP Server 并说清三大原语；能说清什么时候不该用框架。

### P4 · 生产化 + 求职冲刺（第 13–16 周）

**目标：**把项目从"能跑"改造成"敢上线"。**这是"Demo 能跑"和"拿 offer"之间真正的分水岭**——企业招的是能让 Agent 稳定运行的人，不是能写 Demo 的人。

**学什么 · 生产化**

- **可观测性 Tracing**：LangSmith / Langfuse（开源可自托管，推荐）/ Arize Phoenix。每一次模型调用、工具调用、状态转移都要可回放
- **评估 Eval**：这是 Agent 的"单元测试"。构建 20-50 条评测集，用 LLM-as-Judge + 代码断言，跑回归，**把 eval 挂进 CI 当发布门禁**
- **成本控制**：Token 监控、Prompt Caching、模型分级路由（简单的活给小模型）
- **安全**：工具权限最小化、危险操作审批门（HIL）、**把工具返回值当作不可信输入处理**
- **部署**：FastAPI 包装 + Docker + CI/CD + 云服务器上线，全链路亲手走一遍

**学什么 · 求职**

- **简历改造**：把"使用了 LangChain"改成"通过 XX 策略将幻觉率从 X% 降到 Y%"——全部量化
- **技术博客**：写踩坑记录和架构设计思路（知乎/掘金/公众号）。**面试官真的会当场打开你的博客看**，这是绕过学历关的利器
- **开源贡献**：给主流 Agent 框架提 PR，哪怕是文档修复
- **投递节奏**：先投 10 家练手公司试错，复盘面试问题，再冲目标公司

**◆ 产出物**：你的主项目必须有这三样东西：**一个 Tracing 面板截图、一份 Eval 报告、一张成本账单**——而不是只有一个能跑的 `main.py`。外加一篇复盘博客 + 一份已投出并迭代过 2 版的简历。

**过关标准 →** 能完整讲出一次线上故障的排查过程：从 Trace 定位到具体节点、判断是工具描述歧义还是模型推理问题、改完后如何加进 eval 防回归。

> **✓ 关于 P4 的一点强调**
>
> 大多数自学路线到 P3 就结束了，这恰恰是**你最容易超车的地方**。行业数据显示 88% 的生产级 Agent 部署都报告过事故，而绝大多数应届生连"Agent 怎么做单元测试"都答不上来。**只要你能在面试里讲清楚 Eval 体系怎么搭、Trace 怎么看，你就已经超过 80% 的竞争者了。**

## STEP 3 · 2026 框架选型：别再纠结

框架选择的核心原则：**选 JD 命中率最高的那个深挖，其余的了解定位即可。**不要用"我懂五个框架"去面试，要用"我把一个框架用到了生产级"去面试。

| 框架 | 定位 | 学习曲线 | MCP 支持 | 对你的优先级 |
| --- | --- | --- | --- | --- |
| **LangGraph** | 基于图的有状态编排，生产成熟度最高。Checkpoint 持久化、Time-travel 调试、HIL 一等公民。被 Klarna、Uber、LinkedIn 用在生产环境。 | 陡 | 支持 | 主攻 · 必须深挖 |
| **Claude Agent SDK** | Anthropic 官方，与 Claude Code 同源。沙箱执行、MCP 集成深度最好（原生支持 200+ MCP Server）。 | 中低 | 原生最深 | 次选 · 值得会用 |
| **OpenAI Agents SDK** | OpenAI 官方轻量框架，Handoff 架构，内置 guardrails / tracing / sessions，上手最快。 | 低 | 支持 | 会用即可 |
| **CrewAI** | 角色化多 Agent 协作，2-4 小时出原型，心智模型直观。缺点是复杂生产系统会触顶。 | 低 | 部分 | 快速原型用 |
| **LlamaIndex** | 以数据/RAG 为核心，检索能力强。 | 中 | 部分 | 做知识库时补 |
| **Dify / Coze** | 低代码可视化，60k+ star。出 Demo 极快，但抽象层很快变天花板，生产调试困难。 | 极低 | 支持 | 了解即可 · 别当主业 |
| **AutoGen / AG2** | 多智能体对话研究导向。 | 中 | 部分 | 跳过 |

> **◆ 一句话决策法**
>
> 问自己："我的 Agent 最难的部分是什么？" **多角色协调 → CrewAI；跨多步骤的状态分支管理 → LangGraph；靠丰富的工具生态取胜 → Claude Agent SDK；让非工程师也能搭 → Dify。如果你刚开始不知道需要什么 → 先用原始 API 手写两周。**你会因为亲自踩到那些坑，而真正理解框架存在的意义。

## STEP 4 · MCP：2026 年最值得单独投入的一块

如果你只能在这份路线里挑一件"别人还没普遍会、但企业已经开始要"的技能，那就是 MCP。

Model Context Protocol 是 Anthropic 提出的开放标准，被比喻为 **AI 应用的 USB-C**：一次写好一个 MCP Server，Claude、各种 IDE、各种 Agent 框架都能直接调用。它的价值在于网络效应——工具被包装成 MCP Server 后，所有 MCP 兼容系统立即可用。

**必学清单**

- **架构**：Host / Client / Server 三者关系
- **三大原语**：Tools（工具）、Resources（资源）、Prompts（提示模板）
- **传输层**：stdio 与 HTTP + SSE
- **动手**：用 Python 或 TypeScript 写一个自己的 MCP Server
- **发布**：推到 npm / PyPI，并验证能在 Claude Code 或 Cursor 里跑通

**面试加分点**

- **工具契约设计**：不只是写出工具，而是写出模型在模糊场景下也能用对的工具
- **权限最小化**：每个 MCP 连接都是一份凭证，要做最小权限边界
- **提示注入意识**：工具返回值是不可信输入，不能让它直接驱动危险操作
- **知道什么时候不用 MCP**：固定流程用传统连接器更简单更安全

> **⚠ 一个高级判断力信号**
>
> 做一个练习：**把同一个能力实现两遍**——先做成固定工作流（显式输入输出、测失败、测幂等），再只把这一个能力通过 MCP 暴露出去，配只读凭证，测对抗性 Prompt，记录调用日志，对任何写操作加人工审批边界。然后在博客里写清楚：**为什么先用确定性工作流、MCP 在哪一点上真的增加了价值、你刻意没有暴露什么、如何限制了爆炸半径。** 这篇东西在面试里的杀伤力，比十个课程证书都大。

## STEP 5 · 可观测与评估：真正的分水岭

Agent 的不确定性让传统可观测性方案完全失效——**你无法用 HTTP 状态码判断一个"幻觉回答"是不是 Bug**。这就是为什么这块内容值得单独成章。

| 维度 | 传统 APM | Agent 可观测性 |
| --- | --- | --- |
| **输出确定性** | 相同输入 → 相同输出 | 相同输入 → 不同输出 |
| **错误定义** | HTTP 5xx / 抛异常 | **语义错误**：幻觉、答非所问、有害 |
| **调用链深度** | 通常 3-10 跳 | 单次请求可达 10-50 次 LLM 调用 |
| **根因分析** | 堆栈追踪 | 需要**语义级推理路径回溯** |
| **成本模型** | 固定基础设施成本 | 按 Token 动态计费，**成本不可预测** |

### 三大支柱，缺一不可

| 支柱 | 解决什么 | 工具 |
| --- | --- | --- |
| **Trace**<br>追踪 | 发生了什么。每一次 LLM 调用、工具调用、状态转移都记成 Span，可回放 | LangSmith / **Langfuse**（MIT 开源可自托管，推荐自学者）/ Arize Phoenix |
| **Eval**<br>评估 | 质量如何。**Agent 没法写传统单元测试，Eval 就是它的测试体系** | 自建评测集 20-50 条 + RAGAS / DeepEval / Promptfoo + LLM-as-Judge |
| **Debug**<br>调试 | 为什么出错。识别故障模式并根因定位 | 5 类典型故障：**无限循环、工具误用、幻觉行动、上下文溢出、推理漂移** |

> **✓ 给你的项目加上这套东西**
>
> 落地三阶段：
> **① 打基础**：接入 Tracing，加确定性检查（调用的工具对不对、顺序对不对、格式合规吗），从生产 Trace 里人工筛 20-50 条建第一个数据集，跑第一次离线 Eval。
> **② 建闭环**：发布前跑回归测试，把线上失败案例转成数据集样例，**每次改 Prompt 或换模型都跑一次对比实验**。
> **③ 持续监控**：线上采样跑在线评估器，对负面分数、延迟、错误率设告警，被标记的 Trace 回流进数据集。

> **◆ 面试里的黄金叙事**
>
> 准备一个真实故事：**"某个线上 Trace 暴露了问题 → 我判断根因是工具描述歧义 / 缺少护栏 / 模型推理不佳 → 我改了什么 → 如何加进 eval 防回归。"** 行业里能读懂工具调用 Trace 并正确诊断失败根因的人，远少于会接 MCP Server 的人。**这个诊断能力就是议价权。**

## STEP 6 · 三个必须做的项目

项目的选择标准只有一条：**能不能在 15 分钟面试里讲清楚"我做了什么决策、为什么这么做、踩了什么坑"。**数量不重要，深度决定一切。

### 项目 ① · 手写 ReAct Agent（不用任何框架）

带 3-5 个真实工具的完整推理循环，有错误恢复、有防死循环、有对话历史管理。**这个项目的作用不是炫技，是证明你懂原理。**

- **技术点**：原始 API 调用 · Function Calling Schema 设计 · 循环终止条件 · 上下文裁剪
- **必须包含**：README 里的架构图 · 至少 3 个工具 · 工具调用失败的错误回传设计
- **面试话术**："我先手写了一遍，才知道 LangGraph 的 Checkpoint 和条件边到底在替我解决什么问题"

### 项目 ② · 带引用溯源的企业知识库问答 Agent

这是**企业真实需求最集中的场景**，也是 JD 里出现频率最高的业务形态。核心不是"能问答"，而是"答得对且可追溯"。

- **技术点**：文档解析 · 分块策略对比 · Embedding · 混合检索（向量+关键词）· Rerank 重排 · 引用溯源
- **必须包含**：**Eval 报告**（准确率、召回率、幻觉率的量化数字）· Tracing 面板截图 · 不同分块策略的对比实验
- **面试话术**："我把分块策略从固定长度改成语义分块后，答案准确率从 X% 提到 Y%——这是我的 eval 报告"

### 项目 ③ · 多 Agent 系统 + 自建 MCP Server（生产化部署）

用 LangGraph 搭一个多步骤协作系统（如：研究助理 = 规划 → 检索 → 撰写 → 审核），外接自己写的 MCP Server，**完整部署上线**并接好可观测与评估。

- **技术点**：LangGraph 状态图 · Checkpoint 断点续跑 · Human-in-the-loop 审批 · MCP Server 开发 · Docker 部署
- **必须包含**：**Tracing 面板 + Eval 报告 + 成本账单**三件套 · 公开的 MCP Server 包 · 一篇复盘博客
- **面试话术**："危险操作我加了审批门，工具权限做了最小化，工具返回值我按不可信输入处理"

> **⚠ 最常见的失败方式**
>
> 见过太多人收藏了 100 个教程、跟着敲了 50 个 demo，但**从来没有独立从零到一完成过一个项目**。教程项目在面试官眼里等于零——因为其他人交的简历上也是同一份。**你要做的是"从零到一"，不是"跟着做一遍"。**

## STEP 7 · 投递策略：先进场，再换场

第一份工作不一定要进大厂。**拿到一年 Agent 实战经验后，学历和经验门槛对你的影响都会大幅下降。**

| 公司类型 | 推荐度 | 分析 |
| --- | --- | --- |
| **AI 创业公司** | ★★★★★ | 最看重实际能力，不太卡学历，成长最快。**优先投** |
| **传统企业 AI 部门** | ★★★★ | 需求量大，竞争者相对少，能接触到真实业务场景 |
| **AI 应用外包 / 方案商** | ★★★ | 能快速积累项目经验，作为跳板不错，注意别陷在重复劳动里 |
| **实习转正** | ★★★ | 曲线进入大厂体系的有效路径 |
| **大厂正式校招** | ★★ | 有机会，但需要很强的项目 + 面试表现。作为冲刺目标，别作为唯一目标 |

### 三条绕过简历关的路径

- 1. 技术博客：把踩过的坑和架构设计思路写出来：有真实案例：面试官当场在电脑上打开候选人的博客，边看边讨论，最终顺利拿到 offer。**当 HR 搜你的名字能搜到内容时，学历的权重就下降了。**建议至少写 5-8 篇，覆盖 RAG、LangGraph、MCP、Eval 四个主题。
- 2. GitHub 作品集：有 star 的项目就是你的名片：规范的 commit 记录、清晰的 README、架构图、eval 报告。**README 的质量本身就是工程能力的体现**，比项目复杂度更重要。
- 3. 简历改造：全部改成量化表达：❌ "使用 LangChain 开发了知识库问答系统" → ✅ "设计混合检索 + Rerank 方案，通过自建 50 条评测集验证，将答案准确率从 62% 提升至 89%，幻觉率下降 40%"。**后者的面试邀请率至少翻倍。**

> **◆ 时间节奏建议**
>
> 不要等"学完了"再投。**第 12 周就可以开始投练手公司**——面试本身就是最高效的学习反馈，被问倒的地方就是你下一周的学习清单。先投 10 家试错、复盘、迭代简历，再冲目标公司。

## STEP 8 · 面试高频考点自查清单

以下每一条都应该能脱口而出。**答不上来的，就是你接下来两周的补强方向。**

**工程底座**

- SSE 流式输出怎么实现？和普通 HTTP 响应有什么区别？
- Agent 场景为什么必须用异步？`async/await` 的调度原理？
- 接口超时、模型限流、调用失败分别怎么重试？幂等性怎么保证？
- Pydantic 模型校验在工具调用里起什么作用？

**AGENT 原理**

- ReAct 的完整循环是什么？终止条件怎么设计？怎么防死循环？
- ReAct / Plan-and-Execute / Self-Reflect 有什么区别？各自适用什么场景？
- Function Calling 的 Schema 怎么设计才能让模型用对？
- 工具调用失败时，错误信息应该怎么写给模型看？
- 多轮对话的上下文怎么管理？超长怎么办？

**RAG**

- 分块策略有哪几种？各自的取舍是什么？
- 为什么需要混合检索？向量检索的短板在哪？
- Rerank 解决什么问题？放在链路的哪一步？
- RAG 答错了，你怎么定位是检索问题还是生成问题？
- 怎么做引用溯源？为什么企业特别在意这个？

**MCP 与生产化**

- MCP 的 Host / Client / Server 分别是什么？三大原语是什么？
- stdio 和 HTTP+SSE 两种传输方式怎么选？
- 工具权限怎么做到最小化？什么是爆炸半径？
- Agent 怎么做"单元测试"？Eval 数据集怎么建？
- Trace 里能看到什么？怎么从 Trace 定位失败根因？
- Token 成本怎么优化？有哪些手段？

> **✓ 一道几乎必考的开放题**
>
> **"你这个 Agent 上线后，怎么知道它还在正常工作？"**
> 高分答案结构：Trace 全链路埋点 → 线上采样跑在线评估器（LLM-as-Judge + 代码断言）→ 对负面分数和延迟设告警 → 被标记的 Trace 进人工标注队列 → 人工修正的 Trace 沉淀成回归数据集 → **把 Eval 挂进 CI 当发布门禁**。能讲到"生产 Trace 反哺测试集"这个闭环，基本就是 senior 级别的认知了。

## STEP 9 · 避坑清单：这些路走不通

以下每一条都是大量自学者验证过的弯路。**省下来的时间，足够你多做两个项目。**

- ✕ 一上来就啃 Transformer 论文、啃数学推导、啃预训练：你投的是**应用开发岗，不是算法岗**。这些知识在面试里的边际收益极低。你只需要理解到"上下文窗口、Token、Temperature、模型能力边界"这一层就够用。把省下的 200 小时投到 Eval 和部署上，回报率高十倍。
- ✕ 花大量时间学 Prompt Engineering 的"咒语"和技巧合集：2026 年行业的共识是：**Context Engineering 已经取代 Prompt Engineering 成为更高杠杆的技能**。企业要的不是会写漂亮提示词的人，是能决定"什么信息在什么时机进入上下文窗口"的人。别背咒语，去研究上下文管理。
- ✕ 把 Dify / Coze 当成核心技术栈：低代码平台是给非工程师用的。**你靠它拿不到技术溢价**，而且它的抽象层很快就会成为天花板——复杂状态管理、自定义工具逻辑、生产调试全都受限。会用、能讲清楚利弊就够了，别把它写进简历的"核心技能"。
- ✕ 跟着教程敲完 10 个 demo，以为自己会了：教程项目在面试官眼里等于零，因为所有人交的简历上都有同一份。**判断标准很简单：你能不能不看教程，从空白文件开始复现出来？**不能，就是没学会。
- ✕ 只学框架，不手写原理：用框架搭出一个 Agent 大概两小时，但面试只会用框架的人，和懂原理的人**薪资差一档**。花两周手写 ReAct 循环，是这份路线里投入产出比最高的投资。
- ✕ 陷入学历焦虑的内耗：你改变不了过去，但**在 AI 应用这个赛道上，你做出来的东西就是你的学历**。这条路线上，作品集的实际权重高于学校标签——这是它相比传统后端岗最大的红利。
- ✕ 只学不做 / 只做不写：做出来只是完成了一半。**把它写出来（博客）、讲出来（README、面试叙事），才能转化成求职竞争力。**不会表达的项目等于不存在。
